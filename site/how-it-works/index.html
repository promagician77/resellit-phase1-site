How photos get there

The background worker reads each photo from ReSellit (your local app, so nothing goes to a third-party server). The content script turns the photos into files and puts them into Poshmark’s photo picker, exactly as if you had chosen them from disk. Order is kept, and the first photo becomes the cover.

Why values “stick”

Modern forms ignore values that a script just pastes in. The filler types the way a browser does (native value setter plus input and change events), and picks list options by clicking them. In our tests a naive paste registered 0/6 fields; the filler registered 11/11.

No duplicates: the rules

One record per item and marketplace, kept by the extension’s background worker. It makes one decision at a time, so two ReSellit tabs can’t both open a form.

StateWhen you press Send

UnconfirmedThe tab closed before the link was captured, so the item may be live. ReSellit checks your Poshmark listings for the SKU (or you paste the link) before anything else.
Not listed (checked)The check found nothing, so sending again is safe.

Editing a listed item is an update, not a new listing. A fingerprint of what was sent lets ReSellit tell “sent twice” from “changed after listing”. Pushing edits to a live listing is a later phase.

API and browser limits, plainly

  • No public listing API. Poshmark’s CSV Bulk Upload exists, but only for Posh Ambassadors and Brand Partners. A Poshmark job posting describes a developer API for its largest enterprise sellers, but it isn’t open to ordinary sellers.
  • Your browser does the work. Listing happens in your signed-in Chrome on a desktop. Poshmark’s guide says you must have logged into its app recently to list on the web.
  • Your click publishes. Poshmark’s terms bar automated crawling and querying. The extension acts only on the form you opened, and only when you send.
  • Listing caps. Crosslisting tools report a cap of about 300 new listings per 24 hours, and a lower allowance for new accounts.
  • Sales aren’t pushed. Poshmark doesn’t notify third-party tools of sales. Tracking sales (a later phase) means checking your sold items while the browser is open.
  • Not tested on live Poshmark. No Poshmark account was used and no real listing was created. In week 1 the field labels are checked on your signed-in account with the health check, and nothing is published.

When Poshmark changes its site

  1. Found by meaning, not by position. Each field has selectors, then its aria-label, its visible label and its placeholder. Scenario 4 shows the form surviving new IDs and a new field order.
  2. Checked before every fill. A health check reports any field it can’t find. The fill then stops short of “ready” and names the field, instead of guessing.
  3. Fixed with data. The Poshmark adapter is a small JSON file of labels and selectors, with no code in it. A patch is validated and shipped from ReSellit, with no new extension build and no Web Store review. Scenario 5 shows it.
  4. Caught early. A weekly scheduled check opens the create-listing page on a test account, runs the health check and never publishes. It alerts you before your next listing session.

Your extension: adapt or rebuild?

The repo includes an audit script for your existing extension. It reads the manifest and code, runs nothing, and gives a verdict.

node tools/audit-extension.mjs ./your-extension

  1. blockManifest V2. Chrome 139+ no longer runs Manifest V2 extensions.
  2. blockPersistent background page.
  3. gapNo "storage" permission: transfer records would not survive a worker restart.
  4. warnRequests <all_urls>: broader than needed, and a harder Web Store review.
  5. blockUses webRequestBlocking (not available in MV3 for regular extensions).
  6. gapNo content script on Poshmark pages.
  7. blockeval/new Function in: background.js.

Above: a legacy Manifest V2 fixture (verdict: rebuild). Chrome 139 and later no longer run Manifest V2 extensions, so an MV2 extension has to be migrated first. The extension built here audits as adapt (ready).
